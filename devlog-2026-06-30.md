# Session dev — 30 juin 2026

## Diagnostic

Revue complète du projet. Problème central : la qualité des réponses RAG est dégradée par des chunks non pertinents qui arrivent dans le contexte LLM.

Trois causes identifiées :
1. **Scraping capte le bruit** — navigation, vitrines vides, vieux Drupal/Joomla, meta-redirects cassés. BeautifulSoup ne peut pas rendre le JS (FAQs DG vides, ~250 chars).
2. **Pas de reranking** — avec TOP_K=12, les 12 chunks récupérés par similarité vectorielle partent directement au LLM sans tri de pertinence.
3. **Contenu utile inaccessible** — listes de cours, contacts de secrétariat, procédures DGweb se trouvent derrière CAS ou en JS (hors scope POC).

## Décisions architecturales

Stratégie retenue : **scraper large + filtrer avec LLM** plutôt que curation manuelle.

- Le filtre Mistral à l'ingestion score chaque page (0–10) et rejette ce qui n'est pas actionnable pour un étudiant ENS.
- Un reranker Mistral à la query reclasse les TOP_K chunks avant de les passer au LLM, garde les 4 meilleurs.
- La curation manuelle reste valable pour le post-POC (GDoc collaboratif, accès CAS) mais trop limitée pour couvrir tous les départements sans accès institutionnel.

## Implémentations

### `app/ingest_web.py` — Filtre LLM

Nouvelle fonction `filter_with_llm(text, url)` : appelle `mistral-small-latest` avec prompt de scoring, retourne `{"score": 0-10, "keep": bool, "reason": str}`.

Nouveaux flags CLI :
- `--dry-run` : scrape + filtre LLM + affiche les résultats (KEEP/SKIP avec score et raison), **sans ingérer** → à utiliser pour prévisualiser la sélection avant de committer
- `--filter` : scrape + filtre LLM + ingère

Comportement sans flag inchangé (scrape + ingère direct).

### `app/rag.py` — Reranker Mistral

Classe `_MistralRerank(BaseNodePostprocessor)` custom : appelle `mistral-rerank-latest` après la récupération vectorielle, réordonne les nodes par `relevance_score` et garde les 4 meilleurs (sur 12 candidats initiaux).

Pas de package tiers — implémenté directement via `requests.post` sur l'endpoint `/v1/rerank`.

### `app/main.py` — Sources cliquables

Les URLs web sont maintenant des liens markdown cliquables `[titre](url)` au lieu de texte brut. Les PDFs affichent `nom_fichier.pdf p.N`.

## Prochaine étape

Lancer `py app/ingest_web.py --dry-run` pour voir la sélection du filtre sur les ~100 URLs de WEB_SOURCES avant toute ingestion.
